# 系统进阶功能与体验优化方案集

本文档汇集了针对翻译质量排版、断点容错运维、词表校对效率的三个高性价比进阶功能方案。

---

## 方案一：标点符号与中韩混排规范化（Punctuation Normalizer）

### 1. 痛点分析
- 韩语网文常含有连续波浪号 `~~~`、连续问叹号 `?!?!?`、半角句号逗号 `.` `,`、以及韩式三点省略号 `...`。
- LLM 直译后若直接落盘，中文排版显得生硬，缺乏出版级中文小说的视觉美感。

### 2. 核心清洗与规范化规则（可在导出/清洗器中作为可选模块）
1. **省略号规范化**：将韩式连续 3 个点 `...` 或 2 个点 `..` 自动转换为标准中文六角省略号 `……`。
2. **重复标点收敛**：
   - 连续多个问号 `？？？` $\rightarrow$ 收敛为单个 `？` 或双问号 `？？`。
   - 连续多个感叹号 `！！！` $\rightarrow$ 收敛为 `！` 或 `！！`。
   - 连续波浪号 `~~~` $\rightarrow$ 转换为单个全角波浪号 `～` 或破折号 `——`。
3. **盘古之白（CJK 空格优化）**：
   - 在中文与英文字符、数字之间自动添加一个半角空格（例如：`第3卷` $\rightarrow$ `第 3 卷`，`VIP房间` $\rightarrow$ `VIP 房间`）。
4. **英文标点全角化**：
   - 在全中文语境下的半角 `,` `.` `!` `?` `:` 自动替换为对应中文全角符号 `，` `。` `！` `？` `：`。

## 方案二：失败块可视化查看与单块精准重试（Failed Chunks Inspector）

### 1. 痛点分析
- 在翻译 50~200 万字的小说时，可能因网络波动、模型速率限制（HTTP 429）或偶发超时，导致整本书遗留 1~2 个未成功块。
- 目前虽然支持全书续传，但缺乏一个直观的界面去查看“到底哪一章哪一段失败了”，且重新跑整书检查耗时较长。

### 2. 交互与功能设计
- **界面入口**：
  - 当翻译结束且 `failed_chunks > 0` 时，状态栏显示 `⚠️ 存在 X 个未完成块 [查看详情]` 按钮。
- **“失败块查看器”弹窗**：
  - **列表展示**：列出失败块 ID、章节名称、失败原因（如 `Timeout / 429`）与原文段落前 100 字。
  - **右侧详情区**：展示该块包含的完整韩文段落。
  - **操作按钮**：
    1. **`⚡ 仅重试选中断落块`**：独立向 LLM 发起该块的翻译请求，成功后立即将译文写回 `.translation_state.json`，并从失败列表中移除。
    2. **`✏ 手动编辑译文`**：允许用户直接在文本框中粘贴人工翻译，点击保存直接落盘更新存档。

## 方案三：词表条目“一键全书上下文与例句速查”（Glossary Concordance Search）

### 1. 痛点分析
- 人工在表格中确认某个词条（如 `문호철 -> 文浩哲 [person]`）时，经常拿不准这个人在书中具体是谁、是主角的跟班还是反派、性别与身份如何。
- 用户不得不离开工具、打开外部阅读器去搜全文，极其打断校对节奏。

### 2. 交互与功能设计
- **触发方式**：
  - 在“专有名词词表”表格中**双击某一行**，或右键点击 **“🔍 检索全书例句”**。
- **速查弹窗 (`GlossaryConcordanceDialog`)**：
  - 程序瞬间在当前已载入的书籍中正则匹配该韩文词汇。
  - 弹窗列出全书中前 5~10 处出现的上下文句子，并在原句中对该专有名词做**高亮标红**显示。
  - 用户只需扫一眼这几句上下文（例如：“문호철 이사님이 말씀하셨다 / 文浩哲理事说道”），3 秒钟即可准确确认人设与译名准确性。
